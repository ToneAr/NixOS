# NixOS desktop

Flake-based NixOS configuration for a single machine (`tonya-nixos`, user `tonya`).
It sets up KDE Plasma 6 as the main session and Hyprland as a second option at
the SDDM greeter, with Home Manager and plasma-manager handling the user side.

## Usage

Apply the configuration:

```sh
sudo nixos-rebuild switch --flake /etc/nixos#tonya-nixos
```

Update inputs (nixpkgs, home-manager, ...) and rebuild:

```sh
nix flake update --flake /etc/nixos
sudo nixos-rebuild switch --flake /etc/nixos#tonya-nixos
```

The hostname and username are set in `flake.nix`. `networking.hostName` in
`system/configuration.nix` has to match the hostname there.

`nix develop` (or direnv / the VS Code Nix Env Selector) gives a shell with
`nixfmt`, `nil`, `statix` and `deadnix` for working on the config.

## Flake inputs

| Input            | Purpose                                              |
| ---------------- | ---------------------------------------------------- |
| `nixpkgs`        | `nixos-unstable`, to match the Plasma version the configs were written against |
| `home-manager`   | User environment                                     |
| `plasma-manager` | Declarative Plasma settings, shortcuts and panels    |
| `zen-browser`    | Zen Browser (not in nixpkgs)                         |
| `nix-flatpak`    | Declarative Flathub installs                         |
| `omp-theme`      | [ADAPTIVE oh-my-posh theme](https://github.com/ToneAr/ADAPTIVE-oh-my-posh-theme), linked to `~/.config/omp.json` |

## Layout

```
flake.nix            inputs, host definition, Home Manager wiring, dev shell
system/              machine-level NixOS config
modules/             NixOS modules: extra packages, themes and opt-in features
home/                Home Manager config for the desktop session
patches/             patches applied to packages built here
assets/              files copied from the Arch machine
```

Each directory has a `default.nix` that imports the rest, so `flake.nix` only
references `./system`, `./modules` and `./home`.

### `flake.nix`

Inputs, the `tonya-nixos` host, Home Manager wiring (plasma-manager as a shared
module, existing files backed up as `*.backup`) and the dev shell. Sets the
hostname and username, which are passed to every module as `username`.

### `system/`

| File                         | Contents |
| ---------------------------- | -------- |
| `configuration.nix`          | Boot, networking, user, Plasma/SDDM, audio, Bluetooth, fingerprint, SSH, containers/VMs, fonts, memory (zram + systemd-oomd), the `wolfram`/`wolfie` switches |
| `hardware-configuration.nix` | Generated by `nixos-generate-config`; don't edit by hand |
| `memory-limits.nix`          | Home Manager module: Zen Browser in a memory-capped `zen.slice`, KWin memory cap |

### `modules/`

NixOS modules. Most of them build a package and add it to the user's packages;
some also add Home Manager config through `home-manager.users.<name>`.

| File                     | Contents |
| ------------------------ | -------- |
| `applications.nix`       | User applications (including Krohnkite and the `kde-rounded-corners` KWin effect) |
| `flatpak.nix`            | Flathub apps installed by nix-flatpak |
| `breezex.nix`            | BreezeX-Dark cursor theme from the GitHub release, linked into `~/.icons` |
| `yamis.nix`              | YAMIS icon theme |
| `kde-geometry-change.nix` | [Geometry Change](https://github.com/peterfajdiga/kwin4_effect_geometry_change) KWin effect (animates windows moved/resized by programs and scripts) |
| `kde-glass.nix`          | `kwin-effects-glass` KWin effect, built from source with `patches/kde-glass-translucent.patch` |
| `plasma-glass-theme.nix` | `klassy-{dark,light}-glass` Plasma styles and `KlassyDarkGlass`/`KlassyLightGlass` colour schemes, derived from Klassy to match the Panel Colorizer panels |
| `wolframscript.nix`      | Wolfram Engine 15 (`wolframscript`) |
| `wljs-notebook.nix`      | [WLJS Notebook](https://github.com/WLJSTeam/wljs-notebook) AppImage |
| `wolfram.nix`            | Wolfram/Mathematica integration (`wolfram.enable`, off by default) |
| `wolfie.nix`             | [wolfie](https://github.com/ToneAr/wolfie) CLI installer service (`wolfie.enable`, on) |

### `home/` (Home Manager)

| File                          | Contents |
| ----------------------------- | -------- |
| `default.nix`                 | Entry point; imports the rest, installs the window-title widget and Panel Colorizer presets |
| `home-base.nix`               | XDG dirs, session variables, git, delta, direnv |
| `dotfiles.nix`                | klassy, ghostty, kitty, waybar, rofi, swaync, wlogout, wallust configs; fish; oh-my-posh theme; clones the nvim and fish repos |
| `hyprland.nix`                | Hyprland session |
| `plasma/default.nix`          | Plasma workspace theme, fonts, KWin and other settings (from `rc2nix`, pruned by hand) |
| `plasma/panels.nix`           | Plasma panels (hand translated) |
| `plasma/desktop-effects.nix`  | KWin effect settings (blur, glass, rounded corners, ...) |
| `plasma/shortcuts.nix`        | Global shortcuts, including Krohnkite |
| `plasma/window-rules.nix`     | KWin window rules (per-app opacity) |

### `assets/`

Files that aren't in nixpkgs, copied from the Arch machine: Plasma widget,
Panel Colorizer presets, dotfiles, wallpapers, Hyprland helper scripts,
Wolfram/wolfie configs, and wallust seed files. See [`assets/README.md`](assets/README.md) for where each one ends up.

## Things to know

- **Plasma panels are fully managed.** plasma-manager rebuilds the panel
  layout from `home/plasma/panels.nix` on every activation, so panel changes made in
  the GUI are lost on the next rebuild. Panels for extra screens are behind
  the `dockScreens` flag in the same file.
- **Panel Colorizer styling is applied by hand.** The presets are installed,
  but after the first rebuild each colorizer widget has to load its preset
  once ("separated" for the top panels, "separated WIP" for the folder panel).
- **Some config files stay mutable.** Dotfile directories are linked with
  `recursive = true` so tools can write next to their config. Files that
  wallust and nwg-displays regenerate (wallust colours, `hypr/monitors.conf`)
  are only seeded on first activation and are not managed after that.
- **nvim and fish configs come from GitHub.**
  [ToneAr/.neovim](https://github.com/ToneAr/.neovim) is cloned into
  `~/.config/nvim` and [ToneAr/.fish](https://github.com/ToneAr/.fish) into
  `~/.local/share/fish-config`, with `functions/` and `conf.d/` symlinked into
  `~/.config/fish`. These are normal git checkouts: commit, push and pull in
  place. They're only cloned if missing (by the `clone-config-repos` user
  service), so a rebuild never touches them. home-manager owns
  `~/.config/fish/config.fish`, so the repo's `config.fish` isn't used.
- **Secrets stay out of the store.** fish sources
  `~/.config/fish/secrets.fish` if it exists; create it by hand with
  `chmod 600`.
- **Unfree packages are allowed** (`nixpkgs.config.allowUnfree = true`) for
  Chrome, VS Code, Obsidian, Zoom, Wolfram Engine and others in `modules/`.
- **Mathematica is not installed by Nix.** Only the Wolfram Engine
  (`wolframscript`) is. Install the full desktop app with the official
  installer into `~/Wolfram/Wolfram/<version>`, then set
  `wolfram.enable = true` in `system/configuration.nix`.
- **wljs-notebook and wolframscript pin download hashes.** Bumping their
  `version` needs a new hash; build once and copy it from the error.
- **Not enabled:** the DisplayLink dock driver (needs a manually fetched
  unfree driver). The extra panels for the dock's screens are behind
  `dockScreens` in `home/plasma/panels.nix`.
- Don't change `system.stateVersion` or `home.stateVersion`.
